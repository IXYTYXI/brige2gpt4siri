# 实现说明

`Siri / 操作按钮 / 快捷指令 → Bridge 前台 → 中文输入 → HTTPS 服务 → OpenAI 结构化动作 → 客户端校验 → 用户确认 → iOS 公开 API → 本地中文反馈`

## 边界

App Intents 只负责打开应用和传入文本，不假设能调用其他 App 的任意 Intent，也不向 Siri 注入文本。App 在前台处理录音和确认。系统侧边按钮不能由第三方重新定义；“按一下直接说中文”依赖用户配置操作按钮或轻点背面快捷指令。

服务只规划，从不执行设备操作。模型返回的回复也不用于报告执行成功；成功文本由客户端在系统 API 确认后生成，避免第二次模型调用捏造执行结果，同时减少延迟和外传数据。打开其他 App 后 Bridge 可能被系统挂起，因此结果朗读不保证在后台继续；返回 Bridge 可看结果。

## 协议

`POST /v1/plan`，`Authorization: Bearer <BRIDGE_TOKEN>`：

```json
{"text":"明天下午六点提醒我买牛奶","timezone":"Asia/Shanghai","supports_alarm":true}
```

服务端注入当前 UTC 时间；模型参考用户 IANA 时区计算绝对时间。时间格式必须包含秒和偏移，服务端拒绝不可能的日期、过去时间和一年以外时间。执行前显示的是手机当地时间，最终由用户核对。

```json
{"plan":{"action":"create_reminder","app_id":null,"title":"买牛奶","at":"2026-10-05T18:00:00+08:00","reply_zh":"准备创建提醒。"}}
```

错误统一为 `{"error":{"code":"...","message":"中文说明"}}`。模型支持严格 JSON schema；服务端和 Swift 再做独立语义检查。未知动作、非白名单应用、额外字段（服务端）、混用参数均拒绝。

确认绑定到一份不可变 PendingAction，用 UUID 区分。确认有效期五分钟，开始执行之前一次性消费。系统写入过程中禁用重复操作；无自动写入重试。进程被终止的极端时刻，系统写入可能已成功但反馈未显示，用户应先检查系统列表，避免重复提出同一需求。闹钟使用确认 UUID 作为系统 ID。

## 数据与凭据

- 原始录音不发送到 Bridge 后端；Speech 可能根据设备能力由 Apple 处理。
- 用户主动提交的中文文本、时区、闹钟能力发送到自有后端与 OpenAI。
- OpenAI Key 仅存在服务端环境，`store: false`；不声称平台完全无日志或零保留。
- 客户端服务令牌保存在本机解锁后可读的 Keychain，不随设备迁移。
- HTTPS 强制，URLSession 不接受重定向，避免令牌跟随跳转。
- 请求输入不写入服务日志。服务端仅内存限流，不持久化用户文本。
- App 仅在内存保留当前输入/回复；快捷指令传入文本暂存在 UserDefaults 并在读取后清除。闹钟标题、时间及 ID 存在本机用于管理。
- 没有任意 URL、Shell、Swift 代码或自动发送消息执行通道。

## 开发与验证

- `cd server && node --test`：真实本地 HTTP 集成测试及模拟 OpenAI 响应。
- `swift test`：纯 Swift 协议、时间与确认状态测试，无需 API Key。
- `xcodebuild ...`：CI 用 macOS 26 runner 编译完整模拟器 App；不使用签名材料。
- 真实模型理解质量和 Apple 真机权限/响铃不是 mock 测试能证明的，按安装文档执行真机验收。

现阶段是单用户 MVP，未接入历史对话、多用户认证、发布签名、云部署、App Store 隐私申报或真机自动化。
